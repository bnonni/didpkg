Install packages by the DID of the publisher

didpkg is a package manager with the DID (Decentralized Identifier) of the publisher as the root of trust. Put a DWN (Decentralized Web Node) in your DID document, then publish your packages to it. You install with plain npm, pnpm or bun.

didpkg is experimental. Do not use it for production packages.

How it works

  1. Add a DWN. The DID document of the publisher names its DWN. The DWN is the registry of the publisher.
  2. Publish. didpkg publish signs a release record with a key from the DID document. Then it writes the record and the tarball to the DWN. The record holds the SHA-512 digest of the tarball.
  3. Verify. A local shim resolves the DID, reads the DWN, then checks the proof and the digest. Then it gives the package to npm. If a check fails, npm gets an HTTP error.

A static HTTPS mirror is an optional backup copy of the same signed bytes. If the DWN stops, the shim reads the mirror. How didpkg works gives the trust model and the limits.

Install

On Linux or macOS, the install script gets a standalone binary:

curl -fsSL https://didpkg.dev/install | sh

On each OS with Node 22 or later (also Windows), use npm:

npm install --global didpkg

Install didpkg shows how to read the script before you run it, check a manual download, upgrade and uninstall.

Note: didpkg@0.1.0, the release v0.1.0 and this install script are not live yet. Until then, build the CLI from a clone (quickstart, step 1).

Install a package by DID

Start the shim. It runs until you push Ctrl+C.

didpkg shim start

In a second terminal, in your project folder, add 1 line to .npmrc and install:

echo '@didpkg:registry=http://127.0.0.1:2092/' >> .npmrc
npm install @didpkg/hello_did_dht_eszfqrywoegyb5grhitsfrybjnce47y5n8j4ec66bgt9r6skmmwy

The install name holds the package name, the identifier kind (did or xid) and the identifier. A DID name also holds the DID method. The demo has the package hello from 8 publishers. The shim reads each hello package from the demo DWN https://dwn.didpkg.dev:

  • did:web: @didpkg/hello_did_web_nonni.org_pkgs_web is the package of did:web:nonni.org:pkgs:web.
  • did:webvh: @didpkg/hello_did_webvh.v3jo2r5k_qmypg6w1wsqvexs8ej2z4nmaarfr4ekue3vykjmmdhxuij_nonni.org_pkgs is the package of did:webvh:QmYpG6W1WsQVeXs8eJ2z4NMAaRFr4EkUe3vyKJMMdHxUiJ:nonni.org:pkgs.
  • did:plc: @didpkg/hello_did_plc_cpvwafp2z4zqaidjkhyugj3p is the package of did:plc:cpvwafp2z4zqaidjkhyugj3p.
  • did:btcr2: @didpkg/hello_did_btcr2_x1qzpqymyzalnn0m4mg7llfwjewstugrdyznf8qdmde2png2tua07xvjlqu0l is the package of did:btcr2:x1qzpqymyzalnn0m4mg7llfwjewstugrdyznf8qdmde2png2tua07xvjlqu0l.
  • did:key: @didpkg/hello_did_key.jipdria6_z6mkpxedd7bxksn37prfsajv7c6iu3kmg8geeovmjwp2ujry is the package of did:key:z6MkpXeDd7bxkSN37PRfsaJV7C6iu3kMg8Geeovmjwp2UJRY.

6 publishers have the demo DWN in the DID document (or XID document). A did:key or did:jwk document has no services. Thus the shim needs the DWN as an option for these names. A XID name has no host. Thus the shim needs a XID resolver for it. For all 8 names, start the shim with the two options:

didpkg shim start --dwn https://dwn.didpkg.dev --xid-resolver https://nonni.org/pkgs/xid/

The quickstart gives each step and the HTTP errors.

Publish

Make a did:dht DID with a DWN service, register it on the DWN, then publish to the DWN:

didpkg id create main --dwn https://dwn.didpkg.dev
didpkg id register main
npm pack
didpkg publish main hello-1.0.0.tgz --to dwn

The output gives the install name. A static HTTPS mirror is an optional backup copy. Publish a package gives each step, the other DID methods, XIDs, the backup mirror and the key safety rules.
